19 November 2026 - PostgreSQL Global Development Group hari ini mengumumkan rilis PostgreSQL 19, versi terbaru dari database open source paling canggih di dunia.

Penggunaan PostgreSQL untuk kebutuhan bermisi kritis terus meningkat pesat, dan PostgreSQL 19 menjawabnya dengan menyederhanakan administrasi maupun pengembangan untuk beban kerja berskala besar. Rilis ini memperkenalkan perintah REPACK (CONCURRENTLY) sehingga pengguna dapat mengoptimalkan tabel sesuai workload saat ini tanpa mengganggu operasi yang sedang berjalan. PostgreSQL 19 memberi pengguna kontrol yang lebih baik atas stabilitas plan dan performa query melalui extension baru pg_plan_advice. Developer juga akan menemukan banyak fitur menarik di rilis ini, mulai dari dukungan konsistensi "read-your-writes" pada standby hingga perilaku "get or create" yang menghemat satu kali round trip jaringan.

"Selama lebih dari 30 tahun, komunitas open source global telah membangun PostgreSQL menjadi database yang dipercaya organisasi untuk menyimpan data paling kritis mereka," ujar Jonathan Katz, anggota tim inti PostgreSQL. "PostgreSQL 19 melanjutkan komitmen terhadap keandalan tersebut, dengan memberi pengguna cara baru untuk mengelola workload tanpa gangguan dan membangun aplikasi yang mencakup banyak sistem."

PostgreSQL, sistem manajemen data inovatif yang dikenal karena keandalan, ketangguhan, dan ekstensibilitasnya, telah dikembangkan secara open source selama 30 tahun oleh komunitas developer global dan menjadi database relasional open source pilihan bagi organisasi dengan berbagai skala.

Menyederhanakan pengelolaan workload

Tabel yang sering mengalami operasi update dan delete dapat mengalami penumpukan ruang yang tidak terpakai, yang dikenal sebagai "bloat". Kondisi ini juga dapat berdampak signifikan terhadap performa query. Sebelumnya, perintah VACUUM FULL dan CLUSTER digunakan untuk menangani hal ini, tetapi keduanya memiliki trade-off, termasuk mencegah akses ke tabel sampai proses pembersihan selesai. PostgreSQL 19 memperkenalkan perintah REPACK, yang mengklaim kembali ruang kosong dan dapat menyusun ulang data tabel agar sesuai dengan urutan index, dan dengan REPACK (CONCURRENTLY), proses ini dapat dilakukan tanpa memblokir operasi read maupun write. REPACK menggantikan perintah VACUUM FULL dan CLUSTER, yang keduanya tetap tersedia demi kompatibilitas.

Query planner PostgreSQL biasanya memilih plan yang efisien untuk setiap query, tetapi plan tersebut bisa berubah seiring perubahan data, dan terkadang plan yang baru justru lebih lambat. PostgreSQL 19 menambahkan extension pg_plan_advice, yang dapat digunakan untuk menstabilkan pilihan query plan serta bereksperimen dengan berbagai plan menggunakan mini-language "plan advice". Extension pendampingnya, pg_stash_advice, menyimpan plan advice dan menerapkannya secara otomatis ke query berdasarkan query identifier-nya sehingga plan yang lambat dapat diperbaiki tanpa perlu mengubah aplikasi.

PostgreSQL 19 juga membantu autovacuum agar tetap mampu mengimbangi workload di sistem yang sibuk. Autovacuum kini dapat melakukan vacuum pada index menggunakan parallel worker, yang dikendalikan oleh setting baru autovacuum_max_parallel_workers, dan menggunakan sistem penilaian baru untuk menentukan tabel mana yang diproses lebih dulu. Query yang membaca tabel kini dapat secara otomatis menandai halaman sebagai all-visible di visibility map saat dieksekusi sehingga mengurangi pekerjaan yang perlu dilakukan oleh proses vacuum berikutnya. Selain itu, vacuumdb --analyze-only kini juga menganalisis tabel terpartisi ketika tidak ada tabel yang ditentukan.

Rilis ini menambahkan view baru untuk memonitor workload, termasuk pg_stat_lock untuk statistik berdasarkan jenis lock, pg_stat_recovery untuk status recovery, dan pg_stat_autovacuum_scores untuk menunjukkan bagaimana autovacuum memprioritaskan tabel. Opsi baru IO untuk EXPLAIN ANALYZE dan setting terkait di auto_explain melaporkan aktivitas asynchronous I/O. PostgreSQL 19 juga melaporkan jumlah WAL yang ditulis untuk full-page image di pg_stat_wal, EXPLAIN (ANALYZE, WAL), serta di log event vacuum dan analyze.

Peningkatan untuk data terdistribusi

Sebelumnya, PostgreSQL sering mengharuskan pengguna me-restart server untuk mengaktifkan logical replication, yang berpotensi mengganggu workload di lingkungan production. PostgreSQL 19 menyederhanakan inisialisasi logical replication dengan secara otomatis menaikkan effective WAL level menjadi logical saat logical replication slot pertama dibuat. WAL level yang sedang digunakan dapat dilihat melalui setting baru effective_wal_level.

PostgreSQL 19 juga menambahkan dukungan logical replication untuk nilai sequence, yang dapat dipublikasikan menggunakan FOR ALL SEQUENCES dengan CREATE PUBLICATION. CREATE PUBLICATION juga menambahkan klausa EXCEPT untuk mengecualikan tabel saat memublikasikan FOR ALL TABLES, dan CREATE SUBSCRIPTION kini dapat mengambil pengaturan koneksinya dari foreign server (misalnya yang didefinisikan dengan postgres_fdw) melalui klausa SERVER. Selain itu, opsi subscription baru retain_dead_tuples memungkinkan PostgreSQL mendeteksi update yang berkonflik dengan operasi delete yang terjadi bersamaan, dan konflik tersebut dicatat di pg_stat_subscription_stats.

Untuk aplikasi yang mengarahkan read ke standby, PostgreSQL 19 menambahkan konsistensi "read-your-writes" melalui perintah baru WAIT FOR LSN. Sesi di standby dapat menggunakan WAIT FOR LSN untuk menunggu sampai standby selesai me-replay write-ahead log (WAL) hingga mencapai log sequence number (LSN) tertentu, baru kemudian menjalankan query. Dengan demikian, aplikasi dapat membaca data yang baru saja ditulisnya di primary.

PostgreSQL 19 juga meningkatkan query pada foreign table. Dengan opsi baru import_stats, postgres_fdw dapat mengimpor statistik tabel dari remote server saat ANALYZE dijalankan, alih-alih mengambil sampel baris dari tabel remote. Cara ini membantu query planner memilih query plan yang lebih baik.

Peningkatan pengalaman developer dan performa

PostgreSQL 19 menambahkan INSERT ... ON CONFLICT DO SELECT, yang memungkinkan klausa RETURNING mengembalikan baris yang sudah ada ketika terjadi konflik dengan operasi insert, sehingga menyederhanakan pola umum "get or create". COPY kini dapat menghasilkan data dalam format JSON, termasuk dalam bentuk satu array JSON, dan SQL/JSON path language menambahkan metode string seperti lower(), upper(), replace(), split_part(), dan btrim(). Selain itu, window function lead(), lag(), first_value(), last_value(), dan nth_value() kini dapat mengabaikan nilai NULL menggunakan IGNORE NULLS. Fungsi random() kini juga dapat menghasilkan tanggal dan timestamp acak dalam rentang tertentu.

Rilis ini membuat banyak workload lebih cepat tanpa perlu mengubah aplikasi. PostgreSQL 19 meningkatkan performa pemeriksaan foreign key, yang dalam pengujian membuat proses bulk insert hampir dua kali lebih cepat. Rilis ini juga menambahkan lebih banyak optimisasi query planner, seperti mengubah klausa NOT IN menjadi anti-join yang lebih efisien ketika tidak ada nilai NULL, serta melakukan agregasi lebih awal (eager aggregation) sebelum join untuk mengurangi jumlah baris yang diproses. PostgreSQL 19 juga mengembangkan lebih lanjut subsistem asynchronous I/O yang diperkenalkan di PostgreSQL 18. Ketika io_method diatur ke worker (default), PostgreSQL kini secara otomatis menyesuaikan jumlah I/O worker dalam rentang yang ditentukan oleh dua setting baru io_min_workers dan io_max_workers, yang menggantikan setting io_workers. Ada juga peningkatan skalabilitas saat menggunakan LISTEN dan NOTIFY untuk mengirim dan menerima notifikasi pada workload multi-channel.

Terakhir, setting baru password_expiration_warning_threshold memberi peringatan kepada pengguna ketika password mereka akan segera kedaluwarsa.

Perubahan penting lainnya

PostgreSQL 19 menambahkan dukungan sisi server untuk Server Name Indication (SNI), sehingga satu server PostgreSQL dapat menampilkan sertifikat TLS yang berbeda berdasarkan hostname yang digunakan client untuk terhubung. Anda dapat memetakan hostname ke sertifikat dan key masing-masing di file baru pg_hosts.conf. PostgreSQL 19 kini juga mengeluarkan peringatan setelah autentikasi password md5 berhasil. Peringatan ini dapat dinonaktifkan dengan setting md5_password_warnings. Autentikasi password md5 sudah dinyatakan deprecated sejak PostgreSQL 18 dan akan dihapus di rilis mendatang. Jika autentikasi berbasis password diperlukan, gunakan autentikasi SCRAM. Rilis ini juga menghapus dukungan untuk autentikasi RADIUS.

Just-in-time compilation (JIT) kini dinonaktifkan secara default karena estimasi cost yang digunakan PostgreSQL untuk menentukan kapan JIT dijalankan terbukti tidak andal. Jika Anda menjalankan banyak query analitik berukuran besar, JIT mungkin perlu diaktifkan. Bila PostgreSQL di-build dengan dukungan LZ4, metode kompresi default untuk TOAST kini adalah lz4.

Fitur tambahan

PostgreSQL 19 juga menghadirkan berbagai fitur dan peningkatan lain yang mungkin bermanfaat untuk kebutuhan Anda. Silakan lihat release notes untuk daftar lengkap fitur baru dan yang berubah.

Tentang PostgreSQL

PostgreSQL adalah database open source paling canggih di dunia, dengan komunitas global yang terdiri dari ribuan pengguna, kontributor, perusahaan, dan organisasi. Sejak pertama kali dikembangkan di University of California, Berkeley, lebih dari 40 tahun lalu, PostgreSQL terus berkembang dengan laju yang tak tertandingi. Rangkaian fitur PostgreSQL yang matang tidak hanya menyamai sistem database proprietary terkemuka, tetapi juga melampauinya dalam hal fitur database tingkat lanjut, ekstensibilitas, keamanan, dan stabilitas.

Lisensi

PostgreSQL menggunakan PostgreSQL License, lisensi "permisif" yang mirip BSD. Lisensi bersertifikasi OSI ini banyak diapresiasi karena fleksibel dan ramah bisnis, sebab tidak membatasi penggunaan PostgreSQL bersama aplikasi komersial maupun proprietary. Dengan dukungan dari banyak perusahaan dan kepemilikan kode secara publik, lisensi kami membuat PostgreSQL sangat populer di kalangan vendor yang ingin menyematkan database ke dalam produk mereka tanpa perlu khawatir soal biaya, vendor lock-in, atau perubahan ketentuan lisensi.
